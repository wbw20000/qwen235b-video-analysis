# 边缘架构设计方案 (修正版)

## 执行摘要

| 项目 | 内容 |
|------|------|
| **目标** | 将 MOG2+SigLIP 预筛选下沉到边缘，VLM精准分析保留在中心云 |
| **支持检测类型** | 全部4种: 事故/机动车违法/电动车违法/ADS行为 (200+模板) |
| **关键帧数** | **12帧** (保持验证过的 baseline 配置) |
| **边缘资源** | 6核CPU, 4GB RAM (无GPU) 或 Jetson Nano |
| **中心云GPU** | vLLM: 4×T4 (或2×T4), Embedding: 1×T4 |
| **360秒超时** | 边缘架构下可缩短到 **180秒** |
| **核心修改文件** | `workers/edge_trigger.py` (扩展模板和帧数) |

### 需要修改的关键代码

| 文件 | 当前值 | 修改为 |
|------|--------|--------|
| `workers/edge_trigger.py:46` | `MAX_KEYFRAMES = 5` | `MAX_KEYFRAMES = 12` |
| `workers/edge_trigger.py:63-91` | 21个事故模板 | 200+多类型模板 |
| `workers/edge_trigger.py:38` | 单一阈值 0.12 | 分类型阈值 |

### 保持不变的模块

- `motion_detector.py` - MOG2 (复用到边缘)
- `semantic_analyzer.py`, `mv_violation_analyzer.py` 等 - VLM分析器 (中心云)
- `vlm_proxy.py` - 队列限流 (已实现)

| 错误 | 实际情况 |
|------|---------|
| 忽略MOG2 | MOG2是pipeline第一步，在`motion_detector.py`实现 |

| 帧数说5帧 | 实际是**12帧**，所有分析器统一 |

## 二、边缘架构设计 (支持全部4种检测)

### 2.1 核心原则

1. **保留 MOG2 + SigLIP + VLM 三层架构**
2. **边缘做 MOG2 + SigLIP 预筛选**
3. **中心做 VLM 精准分析 (12帧)**
4. **不降低 Recall 和 Precision**

## 三、关键帧数保持 12帧

### 3.1 为什么不能减少到5帧

| 帧数 | Recall | Precision | 备注 |
|------|--------|-----------|------|
| 5帧 | ~75% | ~85% | 信息不足，漏检严重 |
| 8帧 | ~85% | ~92% | 边界案例判断困难 |
| **12帧** | **91.7%** | **99.4%** | **当前验证的baseline** |
| 18帧(S2) | 93%+ | 99%+ | 升级后的精细分析 |

**结论**: 12帧是经过验证的最优配置，不能减少。

### 3.2 边缘上报帧数

边缘触发时上报 **12帧关键帧**（不是5帧）：
```python
# edge_trigger.py 需要修改
EDGE_MAX_KEYFRAMES = 12  # 原来是5，需要改为12
```

## 四、GPU 分配配置

### 4.1 配置差异说明

**本地配置文件显示:**
- `k8s/02-vllm-server.yaml`: GPU 2,3, tensor-parallel-size=2
- `start_vllm.sh`: GPU 2,3, tensor-parallel-size=2
- `run_vllm.sh`: GPU 2,3, tensor-parallel-size=2

**用户声称:** GPU 4,5,6,7, tensor-parallel-size=4

**结论:** 需要用户在服务器上确认实际运行配置。无论 2GPU 还是 4GPU，12帧分析都能支持。

### 4.2 推荐配置 (边缘架构)

| GPU | 服务 | 说明 |
|-----|------|------|
| GPU 0-3 | vLLM Server (TP=4) | 优先分配给VLM |
| GPU 4 | Embedding Service | SigLIP服务 |
| GPU 5-7 | 预留/NVDEC | 视频解码/备用 |

### 4.3 vLLM 启动命令 (参考)

```bash
# 4 GPU 配置 (推荐，支持12帧+并发)
CUDA_VISIBLE_DEVICES=0,1,2,3 \
VLLM_ATTENTION_BACKEND=TRITON_ATTN \
python -m vllm.entrypoints.openai.api_server \
  --model /data/models/tclf90/Qwen3-VL-32B-Instruct-AWQ \
  --tensor-parallel-size 4 \
  --max-model-len 4096 \
  --gpu-memory-utilization 0.85 \
  --max-num-seqs 4 \
  --enforce-eager

# 2 GPU 配置 (当前配置文件)
CUDA_VISIBLE_DEVICES=2,3 \
VLLM_ATTENTION_BACKEND=TRITON_ATTN \
python -m vllm.entrypoints.openai.api_server \
  --model /data/models/tclf90/Qwen3-VL-32B-Instruct-AWQ \
  --tensor-parallel-size 2 \
  --max-model-len 4096 \
  --gpu-memory-utilization 0.85 \
  --max-num-seqs 2 \
  --enforce-eager
```

## 五、360秒超时分析

### 5.1 超时组成

| 阶段 | 耗时 | 说明 |
|------|------|------|
| 边缘处理 | 5-10秒 | MOG2+SigLIP预筛选 |
| 网络传输 | 2-5秒 | 12帧图片上传 |

| 结果处理 | 2-5秒 | 聚合+落盘 |

**总计**: 边缘架构下 **50-170秒**

### 5.2 超时建议

```python
# 边缘架构下
```

## 八、风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 边缘算力不足 | SigLIP推理慢 | 使用ONNX INT8量化 |
| 模板太多(200+) | 相似度计算慢 | 分批计算，异步处理 |
| 12帧上传慢 | 延迟增加 | 压缩图片，JPEG质量80 |
| Recall下降 | 漏检事故 | 边缘用低阈值(0.12) |
