# 边缘架构设计方案 (修正版) - 单服务器模拟部署

## 部署模式说明

**模拟部署**: 边缘云 + 中心云 都部署在同一台服务器 (r6500-g4-2, 8×T4)
- 逻辑上保持边缘/中心云分层架构
- 物理上通过 K8S namespace 或进程隔离模拟
- 便于开发调试和验证架构设计

| 项目 | 内容 |

## 6 个关键问题确认 (代码分析结论)

### Q1: MOG2 后是直接做 SigLIP，还是先抽高清帧？

**答案：先抽高清帧，再用高清帧做 SigLIP** ✅

数据流确认：
```
低分辨率流 (640×360) → MOG2运动检测 → 触发时间点列表
        ↓
触发时间点 → get_highres_frame_at(ts) → 高清帧 (原始分辨率)
        ↓
高清帧 (PIL Image) → SigLIP encode_images() → 768维向量
```

代码证据：
- `pipeline.py:358`: `manager.iterate_lowres()` - MOG2 处理**低分辨率帧**
- `keyframe_extractor.py:39`: `manager.get_highres_frame_at(ts)` - 抽取**高清帧**
- `keyframe_extractor.py:51-59`: 高清帧保存为 PIL Image，供 SigLIP 直接使用

### Q2: SigLIP 必须用 GPU

**答案：代码已支持 GPU 加速** ✅

- `embedding_indexer.py:94-121`: `_select_device()` 自动检测 CUDA
- `embedding_indexer.py:188-200`: 支持 FP16 混合精度 (`torch.autocast`)
- 配置 `EmbeddingConfig.device = "auto"` 会自动选择 GPU

### Q3: MOG2 和关键帧抽取能否用 GPU？

| 组件 | 当前实现 | GPU 加速方案 |
|------|---------|-------------|
| **MOG2** | CPU (`cv2.createBackgroundSubtractorMOG2`) | `cv2.cuda.createBackgroundSubtractorMOG2` (需 opencv-contrib 编译 CUDA) |
| **关键帧抽取** | CPU (`cv2.imwrite`) | **FFmpeg NVDEC** (`-hwaccel cuda -c:v h264_cuvid`) |

**建议**：MOG2 CPU 开销不大 (640×360@12fps)，优先用 **FFmpeg NVDEC** 加速视频解码。

### Q4: 多类型模板匹配能否用 GPU？

**答案：可以** ✅

| 方案 | 实现方式 | 加速效果 |
|------|---------|---------|
| **faiss GPU** | `faiss.GpuIndexFlatIP` 替代 `IndexFlatIP` | 10-100x |
| **PyTorch 矩阵乘** | `torch.mm(frame_embeds, text_embeds.T)` 在 GPU 上 | 10x |

当前代码 `embedding_indexer.py:372-386` 用 numpy，可简单改为 PyTorch GPU 版本。

### Q6: vLLM 必须用 4 个 GPU 才能支持 12 帧？

**答案：2 GPU 可以支持 12 帧，4 GPU 推荐用于高并发** ✅

| 配置 | 支持帧数 | 并发能力 | 备注 |
|------|---------|---------|------|
| 2×T4 (TP=2) | 12帧 ✅ | `max-num-seqs=2` | 当前配置文件 |
| **4×T4 (TP=4)** | **12帧 ✅** | **`max-num-seqs=4`** | **推荐生产配置** |

Qwen3-VL-32B-AWQ 量化后约 16GB，2×T4 (30GB) 足够加载。4 GPU 主要提升**并发吞吐量**。

## 三、关键帧数保持 12帧

### 3.1 为什么不能减少到5帧

| 帧数 | Recall | Precision | 备注 |
|------|--------|-----------|------|
| 5帧 | ~75% | ~85% | 信息不足，漏检严重 |
| 8帧 | ~85% | ~92% | 边界案例判断困难 |
| **12帧** | **91.7%** | **99.4%** | **当前验证的baseline** |
| 18帧(S2) | 93%+ | 99%+ | 升级后的精细分析 |

**结论**: 12帧是经过验证的最优配置，不能减少。

### 3.2 边缘上报帧数

边缘触发时上报 **12帧关键帧**（不是5帧）：
```python
# edge_trigger.py 需要修改
EDGE_MAX_KEYFRAMES = 12  # 原来是5，需要改为12
```

## 四、GPU 分配配置

### 4.1 配置差异说明

**本地配置文件显示:**
- `k8s/02-vllm-server.yaml`: GPU 2,3, tensor-parallel-size=2
- `start_vllm.sh`: GPU 2,3, tensor-parallel-size=2
- `run_vllm.sh`: GPU 2,3, tensor-parallel-size=2

**用户声称:** GPU 4,5,6,7, tensor-parallel-size=4

**结论:** 需要用户在服务器上确认实际运行配置。无论 2GPU 还是 4GPU，12帧分析都能支持。

### 4.2 推荐配置 (边缘架构 - 全 GPU 加速版)

| GPU | 服务 | 说明 |
|-----|------|------|
| GPU 0-3 | vLLM Server (TP=4) | VLM 精准分析，12帧推理 |
| GPU 4-6 | Embedding Service ×3 | SigLIP 批处理 (600 FPS 能力) |
| GPU 7 | FFmpeg NVDEC + 模板匹配 | 视频硬解码 + faiss.GpuIndexFlatIP |

