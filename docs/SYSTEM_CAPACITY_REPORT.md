## 三、处理能力分析

### 单任务处理时间 (有运动)

| 阶段 | 耗时 | 说明 |
|------|------|------|
| MOG2 阶段1 | ~22s | 运动检测 (CUDA) |
| MOG2 阶段2 | ~7s | 帧提取 |
| SigLIP 嵌入 | ~10s | 向量计算 (~80帧) |
| 缓存/发布 | ~1s | Redis 写入 |
| **总计** | **~40s** | 完整处理流程 |

### 吞吐量计算 (所有视频有运动)

| 指标 | 计算公式 | 结果 |
|------|----------|------|
| 单 Pod 吞吐 | 3600s / 40s | 90 任务/小时 |
| 18 Pod 并行 | 90 × 18 | **1,620 任务/小时** |
| 每分钟处理 | 1,620 / 60 | **27 任务/分钟** |

### 输入 vs 处理能力

| 指标 | 数值 |
|------|------|
| 摄像头数量 | 22 路 |
| 分片周期 | 60 秒 |

| 实测输入 | **1,093 任务/小时** (83%) |
| 处理能力 | **1,620 任务/小时** |
| **余量** | 1,620 - 1,320 = **300 任务/小时 (23%)** |

## 五、扩容方案

### 当前瓶颈

- **非瓶颈**: PreProcessor 有 23% 余量
- **潜在瓶颈**: 如果摄像头增加到 27+ 路，需要扩容

### 扩容选项

| 方案 | 操作 | 效果 |
|------|------|------|
| **增加 PreProcessor** | GPU 4-5 各加 3 Pod | +540 任务/小时 |
| **优化 MOG2 参数** | 降低采样率 | 减少 30% 处理时间 |
| **升级 GPU** | T4 → A10 | 2x 处理速度 |

### 理论最大容量

| 配置 | 计算 | 容量 |
|------|------|------|
| 当前 (6 GPU) | 18 × 90 | 1,620/h |
| 满配 (8 GPU) | 24 × 90 | 2,160/h |
| 优化后 | 24 × 130 | **3,120/h** |

## 六、监控指标

### 关键监控项

```bash

kubectl exec -n traffic-vlm redis-0 -- redis-cli XINFO GROUPS video_tasks | grep lag

# 输入速率 (entries-added 增量)
kubectl exec -n traffic-vlm redis-0 -- redis-cli XINFO STREAM video_tasks | grep entries-added
```
